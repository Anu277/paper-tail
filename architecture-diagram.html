Research Paper Agent Architecture

The Research Agent is the only controller, and it works over a corpus of papers rather than generic documents. Every message passes through stage 0 first — a scope gate that keeps this a papers-only assistant rather than an open general-purpose chatbot, closing off a real prompt-injection surface. Retrieval is not a fixed hybrid fan-out — the agent chooses which method(s) to call per question — semantic, BM25, metadata, any combination — and decides on its own whether to follow a paper's citations or search again. Stages are numbered to match the plan; green tags mark every point that actually calls an external LLM.

What changed in this version

  • New: Stage 0, Intent / Scope Gate

    Every message is classified before stage 1 runs — research / greeting / off_topic. Built after a real incident: the first version let a non-research message get "a friendly reply" unconditionally, which correctly skipped searching for a greeting but also answered unrelated general-knowledge questions from the model's own training, and would have complied with an "ignore previous instructions" attempt too. off_topic now gets a firm refusal instead — verified against a real injection-style test message, not just the happy path.

  • New: keyword refinement (Fig. 02)

    A raw user topic is cleaned up before it ever reaches arXiv's search API. Proved empirically that arXiv's search does literal term matching, not language understanding — "i want about quantum computing" returned totally unrelated results, "quantum computing" alone returned exactly on-topic papers. A static stopword list handles this fully; no LLM call needed since the actual failure mode is filler words, not phrasing an LLM would need to rewrite.

  • Citation results rejoin at 5, not 7

    Citation traversal (6) now loops back into Result Processing (5), not directly into the Evidence Evaluator (7). A paper pulled in by following a citation is still a retrieval result — it needs the same dedupe, ranking, and metadata resolution as anything semantic/BM25/metadata search returns. Sending it straight to evaluation would let citation-sourced papers skip a processing step everything else goes through.

  • Domain pivot — research paper agent

    The corpus is papers, not generic documents, and one artifact had to be added rather than relabeled: a citation graph in Fig. 02. Renaming boxes (Research State → Research Workspace, "sources disagree" → "papers report different results") is cosmetic and doesn't change the diagram's shape. Citation traversal (6) reading a real paper → cites → paper graph is not cosmetic — that graph didn't exist anywhere in the ingestion pipeline until now, so stage 6 previously had nothing concrete to query.

  • Adaptive retrieval

    Stage 4 no longer fans out to semantic + BM25 + metadata on every query. Running all three every time is fixed hybrid RAG, not agentic RAG — the agent has to actually choose, or "the agent decides retrieval strategy" is cosmetic. The three methods are now optional branches (4.1–4.3), drawn dashed and animated, selected by the plan at stage 3.

  • Self-contradiction resolved

    Citation traversal (6) is drawn as a conditional branch off the decision (8.4), not an inline stage between 5 and 7. The pasted "final architecture" put stage 6 in three different places across itself — inline in the main diagram, moved to a conditional branch in its own stated correction, then back inline in its closing summary. The conditional version is the one the correction argues for ("the agent decides whether following references is useful, rather than blindly doing it"), so that's the version built here.

  • LLM boundary made explicit

    Stages 0, 1, 3, 7, 9, and 10 are tagged — scope classification, reasoning/decomposition, query formulation, evidence judgment, claim verification, and answer writing. Stages 2, 4, 5, 6, and 8 are mechanical (state storage, retrieval calls, merging, graph traversal, branching) and are not LLM calls, even though 8's branching logic is often implemented by reading an LLM's output from stage 7.

  • Numbering

    Badges 0–10 follow the pasted plan's numbering, with stage 0 added ahead of it. Outcome 8.4 ("need source context") is marked with an asterisk — it's not numbered in the source material, but the conditional reference-traversal branch needs an addressable outcome to route from, so it was added here as 8.4.
